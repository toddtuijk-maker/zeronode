## 二、后门检查结论（重点）

### 结论：未发现传统意义上的恶意后门，但存在 3 个必须处理的风险点

对 `hysteria.sh`、`install_server.sh`、`README.md` 及 git 历史逐行审查后，**没有**发现：

- 反弹 shell、`/dev/tcp`、nc 外联、下载执行未知二进制；
- 挖矿/勒索/远控代码或混淆 base64 载荷；
- 用户数据外传（未发现向非预期域名上传任何数据）；
- 历史中曾存在随后被删除的恶意文件（全部提交均为文本修改，无二进制提交）。

但发现以下 3 个高风险点：

### 风险 1（高）：仓库携带硬编码第三方节点配置 `sing-hy2.json`

`hysteria2-install-main/hy2/sing-hy2.json` 是一份 **sing-box 客户端配置**，硬编码指向：

```json
"server": "91.107.251.1",
"server_port": 2087,
"password": "peyman95",
"obfs": { "type": "salamander", "password": "peyman95" }
```

- 该文件**不在安装脚本的调用链路上**（`hysteria.sh` 中无任何引用），因此不会通过一键安装植入；
- 但它是真实可用的客户端配置。任何用户若把该文件当作模板使用，其全部代理流量都会经过 `91.107.251.1`（Hetzner 机房 IP，疑似作者自建节点），服务端可记录/分析所有流量——属于典型的「引流/监控」陷阱，是审计中最重要的红旗；
- 二开版已删除该文件。

### 风险 2（高）：安装时从第三方仓库动态下载并 root 执行安装器，无任何完整性校验

原版 `hysteria.sh` 安装核心时执行：

```bash
wget -N https://raw.githubusercontent.com/Misaka-blog/hysteria-install/main/hy2/install_server.sh
bash install_server.sh
```

即以 root 权限运行从第三方仓库实时拉取的代码，且无 SHA256/来源校验。若该仓库被接管、账号被盗或内容被投毒，所有使用一键安装的用户会被直接攻陷。同时仓库自带的 `install_server.sh`（旧版）与运行时下载的（新版）不一致，属于供应链自相矛盾。

**二开修复**：改为随脚本分发官方安装器（vendored，标注来源与获取日期），不再运行时下载；安装/升级后对 `/usr/local/bin/hysteria` 做 ELF 魔数检查 + 官方 `hashes.txt` SHA256 比对。

### 风险 3（中）：`curl https://get.acme.sh | sh` 管道执行

仅出现在用户主动选择 Acme 证书的路径（业界标准工具，风险相对可控）。二开版改为先下载到本地、校验内容包含 acme.sh 标识后再执行，并向用户明示该环节。

### 其他与后门相关的观察

- README 中的 `bash <(wget ...InstallNET.sh)` 为 MoeClub 的重装系统脚本（DD），属于用户主动操作，但同样无校验，建议知晓风险后自行判断；
- 全部外链（ip.sb、ipget.net、get.acme.sh、raw.githubusercontent.com）均为公开常规服务，未发现匿名/可疑域名。

## 三、安全缺陷清单（原版）

| 编号 | 位置 | 严重度 | 问题 | 二开修复 |
| --- | --- | --- | --- | --- |
| S1 | `inst_cert` | 严重 | `chmod 777 /etc/hysteria/private.key`：私钥全局可读，任何本地用户可窃取并解密流量 | 私钥 640 属组 hysteria，证书 644 |
| S2 | `insthysteria` | 严重 | 运行时下载第三方安装脚本并 root 执行，无校验（供应链投毒面） | vendored 官方安装器 + SHA256/ELF 校验 |
| S3 | `inst_port` / `unsthysteria` | 严重 | `iptables -t nat -F PREROUTING` 清空机器全部 NAT 转发规则，破坏其他服务；卸载时同样清空 | 独立链 `HY2_NAT` + `--comment hysteria2`，只增删自己的规则 |
| S4 | `inst_pwd` | 高 | 随机密码仅 8 位 hex（32 bit 熵），可暴力枚举；用户可输入任意字符 | `openssl rand -hex 8`（64 bit）+ 长度/字符集校验 |
| S5 | `insthysteria` 写配置 | 高 | 未加引号 heredoc 直接展开用户输入：密码含 `$()`/反引号等可造成 **root 命令注入** | 全部 `printf` 写入，无 shell 二次展开 |
| S6 | `inst_cert` | 高 | 明文 HTTP（`ip.sb`、`ipget.net`）获取公网 IP/解析结果，可被 MITM 篡改 | HTTPS 多源 + `getent` 解析 |
| S7 | `insthysteria` | 高 | 下载的 hysteria 二进制无完整性校验 | 官方 `hashes.txt` SHA256 比对 + ELF 检查 |
| S8 | 客户端文件 | 中 | 密码/配置以 0644 写入 `/root/hy`，本机其他用户可读 | 目录 700、文件 600 |
| S9 | `inst_cert` | 中 | `chmod a+x /root` 放宽 root 目录遍历权限 | 移除 |
| S10 | `inst_port` / `changeport` | 中 | 端口输入无范围/类型校验，非法值直接写入配置；占用检测依赖 `ss` 文本解析 | 1-65535 校验 + UDP 占用检测 |
| S11 | `changeport`/`changepasswd` | 中 | 按行号 `sed` 改配置，脆弱；改密后 `hy-client.yaml` 不更新、`url.txt` 不更新，导致客户端失配 | 状态文件 + 配置整体重写，客户端/分享链接同步 |
| S12 | `changeproxysite` | 中 | 修改 `/etc/caddy/Caddyfile`，而脚本从未安装 Caddy，功能完全失效 | 正确改写 `/etc/hysteria/config.yaml` masquerade |
| S13 | `insthysteria` | 中 | 依赖安装 `PACKAGE_INSTALL` 漏下标，CentOS 等系统实际执行 `apt` 导致失败 | 按实际包管理器（apt/dnf/yum/zypper/pacman/apk）安装 |
| S14 | 卸载 | 中 | 不清理 acme.sh、续期任务、遗留 NAT 规则 | 卸载确认清理 acme.sh/续期；只删自己的 NAT 链 |
| S15 | `insthysteria` | 中 | 默认自签路径不安装 `openssl`，精简系统上直接失败 | 显式 `need_pkg openssl` |
| S16 | 分享链接 | 低 | 密码未做 URL 编码，含 `@`/`?`/`#` 时链接失效 | `urlencode` 编码密码与 SNI |
| S17 | `inst_cert` | 低 | acme 手动向 `/etc/crontab` 追加任务，卸载不清理 | 改用 `acme.sh --install-cronjob`，卸载可选清理 |
| S18 | 服务检查 | 低 | `systemctl status | grep active` 受语言环境影响 | 改用 `systemctl is-active` |

## 六、给使用者的建议

1. 若你正在使用原版一键脚本部署过节点：检查 `/etc/hysteria/private.key` 权限，若为 777 立即 `chmod 600`；确认没有其他人登录过你的 VPS。
2. 不要使用仓库遗留的 `sing-hy2.json`（或任何从网上复制、内含他人服务器 IP 的客户端配置）作为自己的客户端——流量会经过对方服务器。
3. 使用本二开版时，从你自己的 fork/可信渠道获取文件，安装前可自行 `sha256sum` 比对。
4. 生产节点建议：使用 Acme 正规证书 + 强密码 + 开启端口跳跃；私钥属主限制为服务用户 `hysteria`。
